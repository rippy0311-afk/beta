# Core Experience Audit — 2026-09-17 capture

## 元のゲームの糸

Beta は「未完成の浮島を走って渡り、敵を越え、欠けたオーブを集め、基礎を修復し、完成したゲートから次へ進む」横スクロール・ピクセルアクションRPGです。主人公の成長は、世界を直す行為と Air Dash の解放で見せます。操作の核は移動、ジャンプ、Shift Dash、Z攻撃、E修復、STAGE 5以降のX Air Dashです。

## 動画から確認した改善点

- HUDが上部の時間・達成率と下部のCOMPLETEゲージで重複しており、島と次の足場を見る余白を奪っていた。下部ゲージを非表示にした。
- Q/R/T/C/K/M/Vの実験キーが主操作より目立ち、何をすれば先へ進めるかが分かりにくかった。操作ガイドと標準実行から外した。
- ステージの見た目は「工事中の浮島」とオーブ・ゲートが魅力なので、重力反転、時間ずらし、巻戻し、即席足場、コピー能力などの万能能力は世界修復の目的をぼかしていた。実行可能な機能リストから除外した。
- リザルトの個別メダルは再挑戦の目的を明確にするため維持する。追加の等級表示は同じ情報を重複するため採用しない。

## 引退した機能群

重力反転、時間シフト、TODO消去、巻戻し、オーブ投擲/足場化、二段ジャンプ、滑空、敵能力コピー、手描き地図、境界外遠征、急降下、ため攻撃、コンボ/連鎖系、敵を踏む反発、各種自動回復、追加の空中補助を標準ゲームから外した。過去セーブは任意フィールドを無視して読み込めるため、進行を壊さない。

## 今後の安全な統合手順

新しい案は実装前に必ず次の3案を比較し、採用理由をこの文書または実装PRに残す。

1. **既存操作の文脈化**: E・Z・X・Shiftや既存のステージ配置だけで成立させる。新規キーとセーブ形式を増やさず、最優先。
2. **Stage Builderの任意データ化**: `systems/stage-builder.js` のステージ定義に任意値を加え、未定義時は従来のステージになる。地形・敵・風など配置由来の案に使う。
3. **独立サブシステム化**: 新しい `.js` を作り、画面UI・保存・入力を明示して接続する。前2案では表現できず、3つの既存ステージで検証できる場合だけ採用する。

現時点では、操作・保存・物語への影響が最小の **案1** を既定とする。案2・案3は、既存ループを明確に強める根拠と、OFF/未設定時のテストが揃った場合のみ進める。
